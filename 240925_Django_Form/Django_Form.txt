<HTML Form>
지금까지 사용자로부터 데이터를 제출 받기위해 활용한 방법
그러나 비정상적인 혹은 악의적인 요청을 필터링 할 수 없음

유효한 데이터인지에 대한 확인이 필요
-> 유효성 검사: 수집한 데이터가 정확하고 유효한지 확인하는 과정

 - 유효성 검사 구현의 어려움
  유효성 검사를 구현하기 위해서는 입력 값, 형식, 중복, 범위, 보안 등 많은 것들을 고려해야 함
  이런 과정과 기능을 직접 개발하는 것이 아닌 'Django'가 제공하는 Form을 사용 (HTML Form 활용이 이제 아님)

<Django Form> - (from django import forms)
 사용자 입력 데이터를 수집하고, '처리 및 유효성 검사'를 수행하기 위한 도구!!
 유효성 검사를 단순화하고 자동화할 수 있는 기능을 제공

 *) forms에는 textField가 없다.

 {{forms.as_p}} : label, input 쌍을 특정 HTML 태그로 감싸는 옵션

 - Widget: HTML 'input' element의 '표현'을 담당
           (input 요소의 속성 및 출력되는 부분을 변경하는 것)

<Django ModelForm>
 - Model과 연결된 Form을 자동으로 생성해주는 기능을 제공

 *) Django ModelForm: 사용자 입력 데이터를 DB에 저장해야 할 때 (ex. 게시글 작성, 회원가입)
 *) Django Form: 사용자 입력 데이터를 DB에 저장하지 않을 때 (ex. 검색, 로그인)
 
 - Meta class
  - ModelForm의 정보를 작성하는 곳
  - 'fields' 및 'exclude' 속성
   - exclude 속성을 사용하여 모델에서 포함하지 않을 필드를 지정할 수도 있음

<ModelForm 적용>
 - is_valied(): 여러 유효성 검사를 실행하고, 데이터가 유효한지 여부를 Boolean으로 반환
 *) 입력 시 아무것도 입력을 안하는 것과 공백을 입력하는 것은 다름. 에러의 대표적인 예시: 공백 입력
 *) 공백 데이터가 유효하지 않은 이유
  - 별도로 명시하지 않았지만 모델 필드에는 기본적으로 빈 값은 허용되지 않는 제약조건이 설정되어있음

  - save()
   데이터베이스 객체를 만들고 저장하는 ModelForm의 인스턴스 메서드
   save() 메서드가 생성과 수정을 구분하는 법
    - 키워드 인자 instance 여부를 통해 생성할지, 수정할지를 결정

-> Django Form 정리
 1. 사용자로부터 데이터를 수집하고 처리하기 위한 강력하고 유연한 도구
 2. HTML form의 생성, 데이터 유효성 검사 및 처리를 쉽게 할 수 있도록 도움
 *) Django Form, Django ModelForm은 DB에 저장하냐 마냐라는 목적이 다른 것이 뭐가 더 낫다의 개념이 아니다 !!!

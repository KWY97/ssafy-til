- 영화 커뮤니티 웹 서비스의 화면 및 데이터 구성 단계
- 영화 데이터 생성, 조회, 수정, 삭제가 가능한 애플리케이션 완성

3. 해결과정 및 방법

4. 기억하면 좋을 것들

- 모델 건드렸을 때 makemigrations -> migrate 잊지 말기

- GET method
- 서버로부터 데이터를 요청하고 받아오는데(!!!조회!!!) 사용 - 조회할 때만 쓸 것이다.!!
  (물론 생성때도 쓸 수 있다. 그래서 우리도 이 내용을 배우기 전까지 GET을 썼는데, 기술적인 특징이 다르기 때문에 앞으로는 목적에 맞게 쓸 것이다.)
- 특징

  1. 데이터 전송

  - URL의 쿼리 문자열(Query String)을 통해 데이터를 전송
  - ex) http://http://127.0.0.1:8000/articles/create/?title=제목&content=내용

  2. 데이터 제한

  - URL 길이에 제한이 있어 대량의 데이터 전송에는 적합하지 않음

  3. 브라우저 히스토리

  - 요청 URL이 브라우저 히스토리에 남음 (웹서핑 시 뒤로가기가 가능하다.(참고: 스택 방식을 사용하기 때문. 주소를 스택에 쌓아두고 빼고 하며 뒤로가기가 가능한 것) POST는 불가능하다.)

  4. 캐싱

     - 브라우저는 GET 요청의 응답을 로컬에 저장할 수 있음
     - 동일한 URL로 다시 요청할 때, 서버에 접속하지 않고 저장된 결과를 사용
     - 페이지 로딩 시간을 크게 단축

- 사용 예시
- 검색 쿼리 전송
- 웹 페이지 요청
- API에서 데이터 조회

- POST method

- 서버에 데이터를 제출하여 리소스를 변경(!!! 생성, 수정, 삭제 !!!)하는데 사용 (GET 쓸 때(조회할 때) 빼고 전부다 POST 씀)
  (생성, 수정, 삭제는 DB를 조작하는 것이기 때문에 매우 중요)
- 특징

  1. 데이터 전송

  - HTTP Body를 통해 데이터를 전송

  2. 데이터 제한

  - GET에 비해 더 많은 양의 데이터를 전송할 수 있음

  3. 브라우저 히스토리

  - POST 요청은 브라우저 히스토리에 남지 않음 (뒤로가기 불가)

  4. 캐싱

  - POST 요청은 기본적으로 캐시할 수 없음
  - POST 요청이 일반적으로 서버의 상태를 변경하는 작업을 수행하기 때문에

- 사용 예시
- 로그인 정보 제출
- 파일 업로드
- 새 데이터 생성 (예: 게시글 작성)
- API에서 데이터 변경 요청

- STATICFILES_DIRS에 문자열 값으로 추가 경로 설정 (settings.py에 설정)
  STATICFILES_DIRS: 정적 파일의 기본 경로 외에 추가적인 경로 목록을 정의하는 리스트

- settings.py에 MEDIA_ROOT, MEDIA_URL 설정

  - MEDIA_ROOT
    미디어 파일들이 위치하는 디렉토리의 절대 경로
    (MEDIA_ROOT = BASE_DIR / 'media')

  - MEDIA_URL
    MEDIA_ROOT에서 제공되는 미디어 파일에 대한 주소를 생성
    (STATIC_URL과 동일한 역할)
    (MEDIA_URL = 'media/')

- 작성한 MEDIA_ROOT와 MEDIA_URL에 대한 URL 지정

  - 프로젝트의 urls.py에 등록해야함

  - 업로드된 파일의 URL == setiings.MEDIA_URL
  - MEDIA_URL을 통해 참조하는 파일의 실제 위치 == settings.MEDIA_ROOT

     media폴더 안에 images 폴더를 만들고 거기에 업로드 하겠다. 라는 말

  2. 업로드 날짜로 경로 설정 (upload_to='%Y/%m/%d/')
     media 폴더 안에 년도 폴더 만들고 월 폴더만들고 일 폴더 만들고 거기에 업로드 하겠다
     (media/2024/09/26/ 이 경로)

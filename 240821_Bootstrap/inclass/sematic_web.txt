<Semantic Web>
 - 웹 데이터를 의미론적으로 구조화된 형태로 표현하는 방식
 - 의미론적인 마크업이 필요한 이유
   1. 검색엔진 최적화 (SEO)
   2. 웹 접근성 (Web Accessibility)
     - 웹 사이트, 도구, 기술이 고령자나 장애를 가진 사용자들이 사용할 수 있도록 설계 및 개발하는 것
       (ex: 스크린 리더를 통해 전맹 시각장애(들리는 웹을 이용하는) 사용자에게 웹의 글씨를 읽어줌 - 의미론적으로 마크업을 하면 스크린 리더가 강조할 부분은 강조한다던지 훨씬 잘 읽어준다)

 - HTML Semantic Element
   - 기본적인 모양과 기능 이외에 '의미'를 가지는 HTML 요소
   - 검색엔진 및 개발자가 웹 페이지 콘텐츠를 이해하기 쉽다
   ex) 모두 div로 해놓고 구현한 것 보다 header, nav, aside 등을 사용해서 구현

   대표적인 Semantic Element - 기능상 div 태그와 아무런 차이가 없음 (100% 완전 똑같음)
   1. header
   2. nav
   3. margin
   4. article
   5. section
   6. aside
   7. footer

  이렇게 해야 유지보수가 유용해지고, 검색엔진(노출도) 및 개발자가 웹 페이지 콘텐츠를 이해하기 쉽다.

<CSS 방법론>
 - CSS를 효율적이고 유지 보수가 용이하게 작성하기 위한 일련의 가이드라인
 - 규칙은 X, 방법론이기에 안지켜도 돌아감

 1. OOCSS (꼭 기억하기!!!! 중요한 것이라고 함!!!)
   - 객체 지향적 접근법을 적용하여 CSS를 구성하는 방법론
   - 기본 원칙
     1. 구조와 스킨을 분리
     (ex: 버튼을 만든다면 => 버튼의 공통 구조를 정의 + 각각의 스킨(배경색과 폰트 색상)을 정의)
     2. 컨테이너와 콘텐츠를 분리
       객체에 직접 적용하는 대신 객체를 둘러싸는 컨테이너에 스타일을 적용
       스타일을 정의할 때 위치에 의존적인 스타일을 사용하지 않도록 함
       콘텐츠를 다른 컨테이너로 이동시키거나 재배치할 때 스타일이 깨지는 것을 방지

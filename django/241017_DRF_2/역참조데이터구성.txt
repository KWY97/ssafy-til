<단일 게시글 + 댓글 목록>
 단일 게시글 조회 시 해당 게시글에 작성된 댓글 목록도 함께 붙여서 응답

 Nasted relationships (역참조 매니저 활용)
  모델 관계 상으로 참조하는 대상은 참조되는 대상의 표현에 포함되거나 중첩될 수 있음
  이러한 중첩된 관계는 serializers를 필드로 사용하여 표현 가능

  *) models.py로 가서 related_name 으로 원하는 이름으로 바꾸고,
     serializers에서 comment_set 대신 바꾼이름 = ~~~ 하면 이름 바꿔서도 사용 가능


<단일 게시글 + 댓글 개수>
 단일 게시글 조회 시 해당 게시글에 작성된 댓글 개수도 함께 붙여서 응답

 댓글 개수 제공을 위한 새로운 필드 생성
 필드 이름은 마음대로 가능

 ``` 
 number_of_comments = serializers.IntegerField(source='comment_set.count', read_only=True)
 ```

 'source' arguments
  - 필드를 채우는데 사용할 속성의 이름
  - 점(dotted notation) 표기법을 사용하여 속성을 탐색할 수 있음

 !! 특정 필드를 override 혹은 추가한 경우 Meta 클래스의 read_only_fields는 동작하지 않음
 -> 이런 경우 새로운 필드에 read_only 키워드 인자로 작성해야함


<읽기 전용 필드>
 유효성 검사가 필요 없지만 제공은 필요한 것 (사용자에게 입력 받는 것은 유효성 검사가 필요함)
 사용자에게 입력으로는 받지 않지만 제공은 해야하는 경우 (새로운 데이터 값, override 한 값 등)
 새로운 필드 값을 만들어 제공해야 하는 경우

 특징
  - 유효성 검사에게 제외됨
  - 단, 유효성 검사에서 제외된다고 해서 반드시 '생성'로직에서만 사용이 국한되는 것은 아님

 - read_only_fields
  - 기존 외래 키 필드 값을 그대로 응답 데이터에 제공하기 위해 지정하는 경우
  - Meta 클래스의 필드로 쓰기

 - read_only
  - 기존 외래 키 필드 값의 결과를 다른 값으로 덮어쓰는 경우
  - 새로운 응답 데이터 값을 제공하는 경우
  - 새로운 필드의 인자로 쓰기
